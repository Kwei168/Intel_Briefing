反事实遗憾最小化 (CFR) 是为数不多的在 CPU 上运行速度比

反事实遗憾最小化 (CFR) 是少数在 CPU 上运行速度仍比 GPU 快的大型数值工作负载之一。每次迭代都会扫描一个游戏树，其中包含通过通用树接口发出的数百万个小型、相互依赖的收集和分散步骤，其中包含多达数十亿个状态。在 GPU 上，每个内核都在微秒内完成，因此内核启动和框架调度主导了运行时间，并且之前的 GPU 实现已经输给了优化的 CPU 代码。我们观察到，对于固定游戏，除了数值之外，关于 CFR 迭代的所有内容在第一次迭代运行之前都是已知的。我们提出了 GPU-CFR，这是一个基于这一观察结果的编译器和运行时。它将任何游戏一次编译为静态数据流：平坦边缘和信息集数组、预先计算的索引和深度级批处理传递修复了整个操作序列，并且只有求解器状态在迭代之间发生变化。静态机会折叠、深度级执行块和双通道到达缓冲区将框架操作数量减少了 18.1 倍。由于形状、索引和缓冲区地址永远不会改变，因此 CUDA Graph Replay 会记录一次迭代并通过单个图形启动来重播它。在一台 A100 上，在涵盖纸牌游戏、骰子游戏和棋盘游戏的八个游戏套件中，GPU-CFR 在同一加速器上的运行速度比之前最快的 GPU CFR 快 29.8--80.4 倍，在四种最大的游戏上比最快的开源 CPU 实现之一的 LiteEFG 快 14--258 倍。编译后的表示占据了大部分裕度：在没有加速器的八个 CPU 线程上，它已经比 GPU 基准快 2.2--51.1 倍。在 CPU 上，优化路径按位重现参考迭代，并且树构建和图形捕获在第一个求解中就可以收回成本。 GPU-CFR 在不改变更新规则的情况下，在该套件的中型到大型游戏中击败了所有 CPU 和 GPU 基准。
